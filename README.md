## 폴더에 넣으면 할 수 있는 일

| 기능 | 동작 |
| :--- | :--- |
| **문서 → PDF** | 한글·Word·PowerPoint·Excel 파일을 각 데스크톱 프로그램으로 변환해요. |
| **페이지별 PDF** | PDF를 한 페이지씩 나눠 저장해요. 페이지를 이미지로 바꾸지 않아요. |
| **페이지별 JPG** | PDF 각 페이지를 이미지로 저장해요. 기본 200 DPI, 품질 95예요. |
| **PDF → 한글** | 글자·표를 분석해 DOCX를 만들고 한글로 불러와 `.hwp`로 저장해요. |
| **한국어 OCR** | 스캔 PDF를 한국어 우선으로 인식해요. 한국어·영어 데이터가 포함돼 있어요. |
| **창 없는 자동 감시** | 명령프롬프트 없이 폴더를 감시하고, 로그인할 때 자동 시작할 수 있어요. |
| **여러 파일 처리** | 문서별로 순서대로 처리하고, 결과를 파일 이름별 폴더에 나눠요. |
| **원본 보존** | 원본을 삭제하지 않고, 변경된 파일의 결과는 새 번호 폴더에 저장해요. |

> **PDF → 한글은 편집용 복원 기능입니다.** 원래 HWP 파일을 그대로 되돌리는 방식은 아니며, 표·쪽수·글꼴·수식·줄바꿈이 달라질 수 있어요. 한글 2018/2022를 대상으로 구현했지만, 두 버전 모두의 실기 검증을 완료한 상태는 아닙니다. 설치 후 **한글 호환성 점검.bat**을 먼저 실행하세요.

## 실행 조건

### 공통 환경

| 항목 | 필요한 조건 |
| :--- | :--- |
| **운영체제** | Windows 10/11 x64 데스크톱 환경. 전체 프로그램의 macOS/Linux 실행은 지원하지 않아요. |
| **Python** | Python 3.10 이상. 전체 기능 사용에는 **64비트 Python**이 필요해요. 설치 안내 기준은 3.12/3.13이에요. |
| **인터넷** | 최초 설치 및 의존성 복구 때 필요해요. 설치 후 문서 변환은 로컬에서 처리해요. |
| **저장 위치** | 쓰기 가능한 짧은 로컬 경로. 예: `C:\office-converter`. ZIP 안에서 바로 실행하면 안 돼요. |
| **로그인 상태** | 사용자가 로그인한 Windows 세션에서 실행해요. 서비스/서버의 무인 실행용으로 설계되지 않았어요. |
| **실행 정책** | `.bat` 실행이 가능해야 해요. 창 없는 실행과 자동시작 등록에는 Windows Script Host의 `.vbs` 실행도 필요해요. |
| **디스크 공간** | 입력 외에 전체 PDF, 페이지별 PDF/JPG, 임시 파일을 저장할 공간이 필요해요. 고해상도 JPG와 OCR은 용량·메모리 사용량이 커져요. |

Python은 [공식 Windows 다운로드](https://www.python.org/downloads/windows/)에서 설치하세요. 설치할 때 **Add python.exe to PATH**를 선택하고, 설치 후 새 명령프롬프트에서 `python --version` 또는 `py -3 --version`을 확인하세요. 필요한 Python 라이브러리는 `설치.bat`이 각 기능의 `.venv`에 설치합니다.

### 기능별로 필요한 프로그램

| 입력 / 작업 | 지원 확장자 | 추가 설치 조건 |
| :--- | :--- | :--- |
| **PDF 분할·JPG 추출** | `.pdf` | 한글·MS Office 설치 불필요 |
| **한글 → PDF** | `.hwp`, `.hwpx` | Windows용 **데스크톱 한컴 한글** |
| **Word → PDF** | `.doc`, `.docx`, `.rtf`, `.odt` | Windows용 **Microsoft Word** |
| **PowerPoint → PDF** | `.ppt`, `.pptx` | Windows용 **Microsoft PowerPoint** |
| **Excel → PDF** | `.xls`, `.xlsx` | Windows용 **Microsoft Excel** |
| **PDF → 한글** | `.pdf` → `.hwp` | **데스크톱 한글 2018 또는 2022** 대상. Word 설치는 불필요 |

- 한글·MS Office는 정상 설치/활성화 후 **한 번 직접 실행해 초기 설정을 완료**해 주세요.
- 웹 Office, 한글 뷰어, PDF 뷰어만으로는 해당 Office/HWP 변환을 실행할 수 없어요.
- 한글 2018/2022가 함께 설치되어 있으면 Windows COM에 등록된 버전이 사용돼요. 실행 시 버전을 고르는 기능은 없습니다.
- 한글 자동화에는 포함된 `FilePathCheckerModuleExample.dll`을 사용해요. **기존 도구에서 사용하던 32비트 보안 DLL**이므로 설치된 한글과 호환되어야 해요. Python 64비트 요구사항과 한글 내부에서 불러오는 DLL의 호환성은 별개입니다.
- 원본과 같은 글꼴이 PC에 없으면 대체 글꼴로 표시될 수 있어요.
- 별도의 Tesseract 실행 파일은 필요 없어요. OCR 학습 데이터와 PyMuPDF의 OCR 기능을 사용해요.

## 시작하기

### 1. 다운로드와 설치

1. 위의 **ZIP 다운로드**로 받은 파일을 **전체 압축 해제**합니다.
2. 폴더를 `C:\office-converter`처럼 짧은 로컬 경로에 둡니다.
3. 사용할 기능의 폴더를 엽니다: `PDF분할` 또는 `PDF→한글`.
4. 해당 폴더의 **설치.bat**을 실행하고 설치 완료를 기다립니다.
5. `PDF→한글`을 사용한다면 **한글 호환성 점검.bat**을 실행합니다. 만들어진 `호환성 점검\호환성확인.hwp`를 열어 글자와 표를 확인하세요.

두 기능을 모두 쓰려면 **각 폴더에서 설치.bat을 한 번씩** 실행하세요. 각각 독립된 실행환경을 사용합니다. 현재 배포는 Python 기반 실행 스크립트이며, Python이 포함된 단일 EXE 설치 프로그램은 아닙니다.

### 2. 먼저 한 번 변환하기

| 작업 | 파일을 넣을 곳 | 실행할 파일 | 결과 위치 |
| :--- | :--- | :--- | :--- |
| **문서 → PDF / PDF 분할 / JPG 추출** | `PDF분할\변환할 파일` | `한번만 변환.bat` | `PDF분할\PDF 변환 완료` |
| **PDF → 한글** | `PDF→한글\변환할 PDF` | `한번만 변환.bat` | `PDF→한글\한글 변환 완료` |

`PDF분할`은 **전체 PDF·페이지별 PDF·페이지별 JPG를 함께 생성**합니다. 전체 PDF만 필요하면 `전체 PDF` 폴더의 결과를 사용하세요. 현재 기본 실행에는 나머지 두 출력을 끄는 옵션이 없습니다.

### 3. 창 없이 계속 사용하기

1. 사용할 기능 폴더의 **백그라운드 시작.vbs**를 더블클릭합니다.
2. 시작 안내를 닫습니다. 명령프롬프트가 없어도 폴더 감시는 계속됩니다.
3. 입력 폴더에 파일을 넣고 결과 폴더를 확인합니다.
4. 종료할 때는 **백그라운드 종료.vbs**를 실행하고 **상태 확인.vbs**로 종료 여부를 확인합니다.

다음 로그인부터 자동 실행하려면 **로그인 자동시작 등록.vbs**를 실행하세요. 두 기능의 자동시작은 별도로 등록됩니다.

## 사용과 설정

### 실행 파일 안내

| 실행 파일 | 동작 |
| :--- | :--- |
| `설치.bat` | 의존성을 설치하거나 복구해요. 폴더 감시는 시작하지 않아요. |
| `실행.bat` | 실행환경 확인 후, 명령프롬프트가 보이는 상태로 계속 감시해요. 종료는 `Ctrl+C`예요. |
| `한번만 변환.bat` | 시작할 때 있던 입력 파일을 처리하고 종료해요. |
| `백그라운드 시작.vbs` | 명령프롬프트 없이 계속 감시해요. 같은 폴더의 중복 실행을 막아요. |
| `백그라운드 종료.vbs` | 현재 파일 처리를 마친 뒤 종료하도록 요청해요. |
| `상태 확인.vbs` | 실행 중인지, 종료를 기다리는지 확인해요. |
| `로그인 자동시작 등록.vbs` | 현재 사용자의 시작프로그램에 등록해요. |
| `로그인 자동시작 해제.vbs` | 다음 로그인부터 자동 실행을 해제해요. 현재 실행은 별도로 종료해야 해요. |
| `한글 호환성 점검.bat` | PDF→한글 전용. DOCX → HWP 저장·다시 열기·문자 보존을 점검해요. |

한글 변환용 창은 숨기지만 프로그램의 보안 안내·인증·특수 확인창까지 항상 숨길 수 있는 것은 아닙니다. PC가 절전 상태이거나 로그아웃한 동안에는 처리하지 않습니다. VBS가 회사 정책으로 차단되어 있다면 `실행.bat`으로 사용할 수 있어요.

### 결과 폴더

```text
office-converter/
├── PDF분할/
│   ├── 변환할 파일/                    ← HWP·Word·PPT·Excel·PDF 입력
│   └── PDF 변환 완료/
│       ├── 전체 PDF/
│       │   └── 발표.pptx/발표.pdf
│       ├── 페이지별 PDF/
│       │   └── 발표.pptx/발표_001.pdf   ← 페이지마다 파일 하나
│       └── 페이지별 JPG/
│           └── 발표.pptx/발표_001.jpg
└── PDF→한글/
    ├── 변환할 PDF/                     ← PDF 입력
    ├── 한글 변환 완료/
    │   └── 보고서.pdf/
    │       ├── 보고서.hwp              ← 최종 한글 문서
    │       ├── 편집용.docx             ← 중간 편집용 문서
    │       ├── 원본비교.pdf            ← 원본 PDF 사본
    │       ├── 추출문자.txt
    │       ├── 확인사항.txt
    │       ├── 변환보고서.json
    │       └── .complete.json          ← 완료 기록
    └── 확인 필요/                     ← HWP 저장 실패 시 중간 결과 보관
```

`확인 필요`와 `호환성 점검` 등은 필요할 때 생성됩니다. 여러 파일과 하위 폴더도 처리하며, 입력 확장자가 다른 동명 문서는 별도 결과 폴더를 사용해요.

### 여러 파일 · 재처리 · 종료

- 파일 복사가 끝나도록 **크기와 수정 시간이 3초간 안정된 뒤** 처리합니다.
- 여러 파일은 **순차 처리**합니다. 두 기능을 함께 실행해도 한글 COM 작업은 공유 잠금으로 순서를 맞춰요.
- 완료 기록과 결과가 유효한 변경 없는 입력은 건너뜁니다. `.complete.json`을 임의로 삭제하지 마세요.
- 원본이 바뀌거나 결과가 누락되면 기존 결과를 보존하고 `(1)`, `(2)` 같은 새 폴더에 저장합니다.
- 감시 모드에서는 실패한 파일을 30초 간격으로 최대 3회 시도합니다. 원인을 해결한 뒤 다시 시작하세요.
- 종료 요청은 현재 파일 처리가 끝난 뒤 반영됩니다. 큰 스캔 PDF는 OCR 때문에 시간이 걸릴 수 있어요.
- Office 변환의 응답 제한은 기본 300초, PDF→한글의 **한글 저장 단계**는 600초입니다. PDF 분석/OCR 전체 시간 제한을 뜻하지 않아요.
- 시간 초과 후에는 해당 실행에서 같은 프로그램을 사용하는 후속 변환을 중지합니다. 열려 있는 확인창을 정리하고 재시작하세요. 사용자의 모든 Office 프로세스를 일괄 강제 종료하지 않습니다.

### PDF → 한글의 복원 범위

일반 PDF는 원문 글자와 표를 분석하고, 스캔·이미지 위주 페이지 또는 문자 깨짐이 감지되면 OCR을 적용합니다. 중간 DOCX를 한글 안으로 불러온 뒤 HWP로 저장하고, 다시 열어 문자 누락을 검사합니다.

| 항목 | 확인할 점 |
| :--- | :--- |
| **글자와 표 편집** | 페이지 전체를 이미지로 붙여 넣는 방식이 아니라, 글자와 표를 복원해요. 복잡한 표는 수동 보정이 필요할 수 있어요. |
| **글꼴** | 알려진 PDF 글꼴 별칭만 정리하고 원문 글꼴을 유지해요. OCR 글꼴과 대체 글꼴은 원본과 다를 수 있어요. |
| **배치와 쪽수** | 문단·열 너비·줄바꿈·페이지 나눔이 원본과 완전히 같다고 보장하지 않아요. |
| **스캔 이미지** | 사진·도장·손글씨·수식 그래픽이 편집 결과에서 빠질 수 있어요. `원본비교.pdf`로 확인하세요. |
| **문자 보존 비율** | 추출 이후 단계의 누락 점검이에요. OCR 정확도나 시각적 일치율이 아니에요. |
| **HWP 실패** | DOCX만 만들어졌다고 성공 처리하지 않아요. `확인 필요`에 중간 결과와 오류를 보관해요. |

## 업데이트와 다른 PC로 이동

1. 각 기능의 **백그라운드 종료.vbs**를 실행하고 종료를 확인합니다.
2. 입력·결과 폴더를 보관하고, 새 ZIP의 **프로그램 파일 전체**를 교체합니다.
3. 각 기능의 **설치.bat**을 실행해 의존성을 확인합니다.
4. PDF→한글은 호환성 점검 후 다시 시작합니다.

이번 표/서식 수정은 이전 완료 기록을 재처리 대상으로 봅니다. 입력에 남아 있는 PDF는 새 결과 폴더에 다시 변환되며 이전 결과를 덮어쓰지 않습니다.

다른 PC로 옮길 때 `.venv`를 복사하지 말고 새 PC에서 설치하세요. 프로그램 위치를 바꾸면 자동시작도 다시 등록해야 합니다. 기능별 자동시작은 마지막으로 등록한 위치 하나를 사용합니다. 현재 자동 업데이트 기능은 없습니다.

## 문제 해결

| 증상 | 확인할 내용 |
| :--- | :--- |
| **Python을 찾지 못해요** | 64비트 Python을 설치하고 PATH 또는 `py` 실행 여부를 확인하세요. 새 명령프롬프트를 열어 다시 실행하세요. |
| **설치가 실패해요** | 인터넷·프록시·보안 정책과 `설치기록.log`를 확인하세요. 현재 Python에 맞는 바이너리 패키지가 없으면 3.12/3.13 x64 환경으로 설치해 보세요. |
| **Office 파일만 실패해요** | 해당 데스크톱 앱이 설치·활성화됐는지, 직접 파일을 열 수 있는지 확인하세요. 웹 버전/뷰어로는 변환되지 않아요. |
| **한글 보안 모듈/COM 오류가 나요** | 한글을 직접 실행해 초기 설정을 완료하고 호환성 점검을 실행하세요. 설치 버전과 보안 DLL 호환성도 확인하세요. |
| **HWP 대신 DOCX만 있어요 / 확인 필요로 가요** | `변환보고서.json`의 `hwp_error`와 `실행기록.log`를 확인하세요. HWP 저장 단계가 실패한 결과입니다. |
| **원본과 모양이 달라요** | 최신 프로그램 전체를 적용하고 같은 글꼴이 설치돼 있는지 확인하세요. 복잡한 병합 표·수식·스캔은 직접 비교해야 해요. |
| **파일을 넣어도 반응이 없어요** | 입력 폴더·확장자와 `상태 확인.vbs`를 확인하세요. 이미 완료한 동일 파일은 건너뛰며, 실패 3회 후에는 재시작해야 해요. |
| **백그라운드가 시작되지 않아요** | 먼저 `설치.bat`을 실행하세요. `백그라운드오류.log`를 확인하고 VBS 차단 환경에서는 `실행.bat`을 사용하세요. |
| **종료가 바로 안 돼요** | 현재 문서 처리를 마칠 때까지 기다린 뒤 상태를 확인하세요. 한글/Office의 확인창이 떠 있는지도 확인하세요. |
| **Excel PDF 쪽수가 많아요** | 원본 Excel의 인쇄 영역, 용지 크기, 배율, 페이지 나누기를 조정하세요. |
| **암호 파일·긴 경로에서 실패해요** | 암호가 없는 사본을 사용하고 짧은 로컬 경로로 옮겨 주세요. |

로그는 각 기능 폴더에 있어요: `실행기록.log`(변환), `설치기록.log`(설치), `백그라운드오류.log`(백그라운드 오류). 로그·보고서에는 문서 이름과 경로가 포함될 수 있으니 공개 이슈에 올릴 때는 확인해 주세요.

해결되지 않으면 [Issues](https://github.com/chani337/office-converter/issues)에 **Windows/Python 버전, 한글·Office 버전, 입력 확장자, 오류 문구, 재현 순서**를 남겨 주세요.

## 소스에서 실행하기

```sh
git clone https://github.com/chani337/office-converter.git
cd office-converter
```

Windows에서 각 기능 폴더의 `설치.bat`을 먼저 실행하세요. 아래 명령은 **해당 기능 폴더에서 명령프롬프트(cmd)**로 실행하는 예시입니다.

### PDF분할

```bat
.venv\Scripts\python.exe split.py --once
.venv\Scripts\python.exe split.py --dpi 300 --timeout 600
```

DPI는 72~600, Office 변환 대기 한도는 10~3600초입니다. 기본값은 200 DPI·300초예요.

### PDF→한글

```bat
.venv\Scripts\python.exe split.py --once
.venv\Scripts\python.exe split.py --ocr always
.venv\Scripts\python.exe split.py --language kor+eng
.venv\Scripts\python.exe split.py --language eng --timeout 900
```

기본값은 OCR 자동 판단·한국어(`kor`)·한글 저장 대기 600초입니다. `--ocr always`는 원문 글자가 있어도 모든 페이지를 OCR하므로 필요한 경우에만 사용하세요. 위 옵션은 해당 수동 실행에 적용되며 VBS 기본 설정을 변경하지 않습니다.

두 기능 폴더는 각각 독립 실행할 수 있어요.

| 파일 | 역할 |
| :--- | :--- |
| `bootstrap.py` | 가상환경 설치·의존성 검사·실행 |

| `converter.py` | Windows 한글/Office 자동화 |
| `runtime.py` | 중복 실행 방지·한글 작업 공유 잠금 |
| `background.pyw` | 창 없는 실행·상태·로그인 자동시작 |
| `PDF→한글/prepare.py` | PDF 분석·OCR·DOCX 생성 |
| `PDF→한글/docx_compat.py` | 한글 불러오기용 테두리·병합 셀 너비·글꼴 정리 |
| `PDF→한글/reverse.py` | HWP 결과 검증·완료 기록·실패 결과 보관 |
| `PDF→한글/check.py` | 설치된 한글 호환성 점검 |
| `PDF→한글/tessdata/` | 한국어·영어 OCR 모델과 무결성 정보 |

각 기능 폴더에서 실행합니다. Office COM 호출 테스트에는 모의 객체를 사용하므로, 테스트 통과만으로 실제 한글/Office 설치 환경이 검증되는 것은 아닙니다.

```bat
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

입력 문서·변환 결과·로그·가상환경은 `.gitignore`로 제외합니다. 개발 테스트는 임시 문서를 생성하고, 사용자 문서는 저장소에 포함하지 않습니다.

## 검증 범위

- PDF분할: PDF/JPG 처리, 여러 파일, 완료 기록과 실패 처리 등 **자동 검사 28개**.
- PDF→한글: 한국어 OCR, 표, 혼합 페이지, HWP 실패 보관, DOCX 불러오기, 표/글꼴 보정 등 **자동 검사 14개**.
- 실제 PDF 샘플에서 표 열 너비·병합 셀·세로 테두리 요소와 원문 줄바꿈을 확인했어요.

**검사는 macOS에서 실행했습니다. Windows 배치/VBS, 실제 Office COM 변환, 한글 2018/2022의 최종 화면 일치에 대한 실기 검증은 완료하지 않았습니다.** HWP 저장·재열기 호출은 모의 검사와 구분해서 판단해야 해요. 자신의 PC에서는 포함된 호환성 점검과 실제 문서 변환으로 확인하세요.

## 변경 기록

| 변경 | 내용 |

## 사용 라이브러리와 포함 파일

[PyMuPDF](https://pymupdf.readthedocs.io/), [pdf2docx](https://github.com/ArtifexSoftware/pdf2docx), [python-docx](https://python-docx.readthedocs.io/), [pywin32](https://github.com/mhammond/pywin32) 등을 사용합니다. Python 패키지와 포함 파일의 라이선스는 각 프로젝트의 조건을 따릅니다. OCR 모델의 출처·SHA-256은 `PDF→한글/tessdata/manifest.json`, Apache-2.0 전문은 `PDF→한글/tessdata/LICENSE`에 있습니다.

한컴 한글과 Microsoft Office는 이 저장소에 포함되지 않으며 별도로 설치해야 합니다. 한글 자동화 보안 DLL은 기존 PDFLocal 도구에서 사용하던 파일을 유지했습니다. 이 저장소 전체에 MIT 같은 별도 통합 라이선스를 지정하지 않았습니다.
