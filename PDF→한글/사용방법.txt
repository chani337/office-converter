PDF→한글 (한글 2018 / 2022 대상)

1. 설치.bat: 최초 한 번 실행. 인터넷 연결이 필요합니다.
2. 한글 호환성 점검.bat: 설치된 한글에서 실제로 DOCX를 HWP로 저장하고 다시 읽습니다.
   '호환성 점검' 폴더의 호환성확인.hwp를 열어 문장과 표까지 확인하세요.
3. 백그라운드 시작.vbs: 명령프롬프트 없이 감시 시작.
4. 변환할 PDF 폴더에 PDF를 넣으세요. 여러 개를 넣으면 문서별로 순서대로 처리합니다.
5. 한글 변환 완료 폴더에서 문서명.pdf 폴더를 열어 결과를 확인하세요.

결과 예시
한글 변환 완료\보고서.pdf\
  보고서.hwp            한글에서 편집 가능한 최종 문서
  편집용.docx           한글 저장 전 중간 결과 (Word 설치 불필요)
  추출문자.txt          추출/OCR한 문자를 비교하기 위한 파일
  원본비교.pdf          원본 PDF의 사본
  확인사항.txt          OCR 사용 페이지와 확인할 내용
  변환보고서.json       페이지별 처리/자동 검사 기록
  .complete.json        중복 처리 방지 기록 (삭제하지 마세요)

필요한 환경
- Windows 10/11 64비트, Python 3.10 이상 64비트 (3.12 또는 3.13 권장)
- 데스크톱 한글 2018 또는 2022 설치/활성화/최초 실행 완료
- 뷰어만 설치된 환경에서는 HWP를 저장할 수 없습니다.
- 두 한글 버전을 함께 설치했다면 Windows에 COM으로 등록된 버전이 사용됩니다.
- 기본 형식은 두 버전이 공통으로 읽는 HWP 5.x입니다. HWPX 전용 기능은 사용하지 않습니다.
- 제공되는 보안 DLL은 기존 PDFLocal의 32비트 DLL입니다.
  설치된 한글의 비트 수와 호환되지 않으면 호환성 점검에 실패할 수 있습니다.
- OCR용 한국어/영어 학습 데이터는 포함되어 있습니다. Tesseract 실행 파일을 별도로 설치하지 않습니다.
- 입력 문서는 외부 서버로 업로드하지 않습니다.

추출/복원 방식
- 원문 글자가 있는 PDF는 글자·표·이미지 배치를 분석합니다.
- 이미지가 대부분인 페이지, 글자가 없는 스캔본, 깨진 문자 페이지는 OCR합니다.
- 한국어 우선 OCR이 기본값입니다. 선명한 인쇄 문서를 기준으로 설계했습니다.
- 스캔 표는 긴 선을 제거한 후 글자를 인식하고, 표 선을 다시 추정하여 배치합니다.
- 원문 글꼴을 유지하고 알려진 PDF 글꼴 별칭만 Windows 글꼴 이름으로 정규화합니다.
  원문 글꼴이 PC에 없으면 대체 글꼴로 표시될 수 있습니다.
- 문장/표 편집이 목적입니다. 원본과 완전히 같은 쪽 배치/쪽수는 보장하지 않습니다.
- 복잡한 다단 문서, 테두리 없는 표, 병합 셀, 수식, 손글씨, 기울어진/흐린 스캔은 수동 확인이 필요합니다.
- OCR 페이지의 사진/도장/수식 그래픽은 편집 결과에서 빠질 수 있습니다.
  원본비교.pdf는 변경하지 않은 원본 사본입니다.
- OCR 결과를 임의로 맞춤법 교정하거나 숫자를 추측해 바꾸지 않습니다.
- 문자 보존 검사는 추출→DOCX→HWP 단계의 누락 점검입니다.
  OCR이 처음부터 잘못 읽은 글자는 검출할 수 없으며 OCR 정답률을 뜻하지 않습니다.

실패와 중지
- HWP 저장 실패 시 완성 결과로 표시하지 않습니다.
  '확인 필요' 폴더에 DOCX, 원본비교.pdf, 추출문자, 오류 보고서를 보관합니다.
- PDF 자체가 손상되어 분석하지 못하면 실행기록.log에 실패를 남깁니다.
- 자동 감시에서는 실패 파일을 최대 3회 처리합니다. 원인을 해결한 뒤 프로그램을 다시 실행하세요.
- 한글 COM 응답 제한은 기본 600초입니다. 응답이 없으면 해당 실행의 추가 HWP 저장을 중지합니다.
- 종료 요청은 현재 PDF의 OCR/문서 복원을 마친 뒤 반영됩니다. 큰 문서는 오래 걸릴 수 있습니다.
- 상태 확인.vbs / 백그라운드 종료.vbs / 로그인 자동시작 등록.vbs / 해제.vbs 제공.
- PC가 켜져 있고 로그인한 동안 동작합니다. 절전/로그아웃 동안에는 처리하지 않습니다.
- 한글 창은 숨기지만 특정 확인창은 나타날 수 있습니다.
- PDF분할과 함께 실행하면 한글 저장 작업은 공유 잠금으로 순서대로 처리합니다.

수동 실행 옵션 (이 폴더에서 명령 프롬프트)
.venv\Scripts\python.exe split.py --once
.venv\Scripts\python.exe split.py --ocr always
.venv\Scripts\python.exe split.py --language kor+eng
.venv\Scripts\python.exe split.py --language eng --timeout 900
always는 모든 페이지를 OCR합니다. 기본 자동 판단에서 문자 깨짐을 놓쳤을 때 사용하세요.
외국어가 많은 문서는 kor+eng 또는 eng로 바꿔 비교하세요.

검증 범위
macOS에서 한국어 일반 PDF/스캔 PDF/표/혼합 페이지의 추출과 DOCX 생성 테스트를 수행했습니다.
HWP 파일 저장, 다시 열기, 숨김 창, 텍스트 검사 호출은 모의 객체로 테스트했습니다.
실제 한글 2018/2022의 설치 환경 검증은 포함된 호환성 점검.bat으로 확인해야 합니다.

DOCX 불러오기 수정 (오류 보고서 반영)
한글 안으로 DOCX를 불러올 때 insert:true를 사용합니다.
OOXML 형식을 먼저 지정하고, 실패하면 문서를 비운 뒤 자동 인식 + insert:true로 재시도합니다.
두 시도가 모두 실패하면 HWP 저장 성공으로 처리하지 않습니다.
근거: https://forum.developer.hancom.com/t/topic/1639
업데이트할 때는 백그라운드 감시를 종료하고 최신 프로그램 파일 전체를 교체하세요.
표/서식 수정에는 docx_compat.py, prepare.py, reverse.py도 필요합니다.
다시 시작하면 변환할 PDF에 남아 있는 미완료 문서를 재처리합니다.
